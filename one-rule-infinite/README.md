# 一条规则，长出无限

从一根枝条开始，看简单的规则如何创造复杂的世界 —— 然后再往外走两步：
从一棵树，到一张知识网络，再到宇宙中的巨大结构。

- **影片**：一部 133 秒的无声动态图形短片。
- **互动**：生长实验室（分叉角 / 每节点分支数 / 长度衰减 / 层数 / 叶片）、
  三种自然分支、自相似层数、可点开的知识依赖网络、可换种子的宇宙网。
- **视频导出**：`npm run export:mp4` → `out/one-rule-infinite.mp4`。

画面里没有一张照片、一段视频或一张预制图片。
每一根枝条、每一片叶脉、每一条河流、每一条技术连线、每一段宇宙丝线
都是运行时算出来的 SVG。

## 三条主线

| 阶段 | 讲什么 | 关键结论 |
|---|---|---|
| 一 · 自然如何生长 | 分叉、递归、L-系统、自相似 | 重复简单规则可以长出复杂的植物状结构 |
| 二 · 知识与技术如何演进 | 前置依赖、跨枝条汇合、有向无环图 | 一个发现可以打开多个方向，一个复杂成果也可以建立在多个前置之上 |
| 三 · 宇宙如何形成宏观结构 | 丝状结构、团块、空洞 | 大尺度结构由引力下的物质演化形成，与前两者成因不同 |

**三者不是同一条公式的三个化身。** 形态相似不等于成因相同，这一点在页面与影片里都写明了。
第二阶段的技术名称是**虚构的示意例子**（用来讲清依赖关系），第三阶段的宇宙网是
**受真实宇宙网启发的程序化可视化**，两者都没有冒充真实数据。

## 导出 MP4

```bash
npm run export:mp4    # -> out/one-rule-infinite.mp4
npm run film:preview  # Remotion Studio，逐帧调时间轴
npm run film:still    # 导出一张静帧快速校对
```

实测输出：`h264 / yuv420p / 1920x1080 / 30fps / 3990 帧 / 133 秒 / 无音轨`。
首次执行会把 Chrome Headless Shell 下载到本项目自己的 `node_modules/.remotion/`。

规格集中在 `src/story/timeline.ts`（FPS、宽高、每个场景的起止帧），`remotion/Root.tsx` 直接读同一份配置。

## 影片时间轴

| # | 场景 | 起点 | 内容 |
|---|---|---|---|
| 1 | 一颗种子 | 0:00 | 一个几乎看不见的点，长出主干、分叉、再分叉；镜头随代数平稳拉远 |
| 2 | 分叉 | 0:16 | 只看一根枝条长到末端长出两根新的；每一代把新长出来的部分点亮 |
| 3 | 三种分支 | 0:32 | 枝条 → 叶脉 → 河流，镜头连续过渡；同时讲清楚「像，但成因不同」 |
| 4 | 规则 | 0:50 | `F → F[+F]F[-F]` 逐字浮现，符号逐个解释，然后看着它作用在一根枝条上 |
| 5 | 从简单到复杂 | 1:08 | 一层层往上加，镜头一路后退；右上角开一个「局部放大」窗口对照自相似 |
| 6 | 不只是分叉 | 1:26 | 树枝照旧长出 → 枝条变成路径、分叉点变成节点 → 横跨枝条的连线出现 → 有向无环图 |
| 7 | 宇宙网 | 1:48 | 镜头继续后退，知识网络淡出，丝状结构、团块与巨大的空洞接管画面 |

## 抖动是怎么修掉的

旧版本里，枝条一长出来画面就抖。根因不是动画太快，而是**镜头每帧都在追一个正在变化的东西**：

1. `fitCamera(boundsAt(plan, t), growingTip(plan, t), …)` —— 包围盒每帧都不一样，
   缩放就每帧都在变，整棵树看起来在「呼吸」；
2. `growingTip` 是时间的**不连续**函数：生长顺序在枝条之间跳，梢头会突然从一根枝条
   甩到另一根，画面被一下一下地抽动；
3. 第一根枝条出现前包围盒是空的，`fitCamera` 会从「原点特写」硬跳到全景；
4. 叶片的摆动用 `performance.now()` 算，而影片用帧号算 —— 两边对不上，也不可复现；
5. 每一帧 React 重新渲染整棵树，已经长好的枝条也跟着一起重算。

现在的做法：

- **镜头只由参数决定。** `generationFramings(plan, viewport)` 一次算出「每一代长完时的取景」，
  `growthCamera()` 只在两代之间按进度插值，`cameraAt(keys, t)` 处理转场。
  没有任何一帧会临时重新取景。取景只随代数单调拉远，不会来回呼吸。
- **生长分两层。** `useGrowthLayers(plan, time)` 返回 `done`（已长完，身份稳定）
  与 `growing`（当前这一代）。`done` 只在跨代时重算一次，已完成的枝条永远不再进入每帧的重算。
- **两个时钟统一。** 叶片摆动交给 CSS（合成器上的 `rotate`），相位由叶子位置决定，
  不占 JavaScript 主线，网页与 MP4 完全一致。
- **每一代都有时间底线。** 只按枝条数量分时间的话，第 1 代只能拿到 1%，
  两根枝条在几帧内长完、镜头被猛地一甩。`planGrowth` 的 `minShare` 给每代一个底线。
- **有回归测试守着。** `src/story/stability.test.ts` 逐帧采样 2400 步，断言：
  同一时刻必得同一镜头、缩放单调不增、每步位移 < 1.5 个世界单位、第一帧就是有效取景。

## 工程上的关键决定

- **一部影片，两个消费者。** `GrowthFilm({ frame })` 是纯函数：只接收帧号，
  不读时钟、不读滚动、不用定时器、不用 `Math.random()`。
  网站用 rAF 换算帧号喂给它，Remotion 用 `useCurrentFrame()` 喂给它 —— 两边是同一部片子。
- **确定性随机。** 树的自然抖动、宇宙网的团块位置都来自 `mulberry32(seed)`。
  同一个种子永远长出同一棵树、同一片宇宙，所以网页第 400 帧和 MP4 第 400 帧一模一样。
- **生成与绘制分离。** `lib/lsystem.ts` 只负责把规则变成枝条（纯数据、有单测），
  `lib/techgraph.ts` 只负责把依赖变成图，`lib/cosmos.ts` 只负责把种子变成结构；
  `viz/` 只负责画，`story/` 只负责按帧取状态。
- **依赖图必须过测试。** `checkTechGraph()` 断言：没有环、前置都存在、
  层级严格递增、确实存在多前置的汇合节点与横跨枝条的连接。
  构建时还会用 `dependsOn()` 挡掉任何会成环的汇合边。
- **节点带真实父指针。** 海龟解释时记录 `Segment.parent`（来自 `[` 栈）。
  只靠「端点坐标重合」判断父子关系会把兄弟枝条误判成父子。
- **降级。** 跟随系统 `prefers-reduced-motion`：影片停在第一帧并提示可以逐章查看；
  实验室与其它章节照常可用，所有文字信息在关掉动画后仍然完整。

## 数学上刻意保持的准确

- 三种自然分支形态相似，但**生成机制不同**：
  树是海龟按规则走的，叶脉是在一片有限的叶子里排布的，河流是一路向下游汇合的。
- 「无限」说的是规则可以继续迭代，**不是**有限时间内画出了无穷多个分支；
  影片与页面都明确说明屏幕上只有画出来的这几层。
- L-系统只是能生成植物样式的**简化规则**，不代表所有真实植物都这样生长。
- 实验室里的「第 n 层节点数 = bⁿ」是**理想化的规则模型**，页面在统计表下面写明了这一点。
- 知识依赖网络里的技术名称是**虚构的示意例子**，不代表真实技术史或因果顺序。
- 宇宙网是**受真实宇宙网启发的程序化可视化**，没有使用任何真实观测数据；
  它的成因（引力下的物质演化）与树、与知识网络都不同，页面与影片都点明了。

## 怎么打倒它

```bash
npm test                                   # 65 个单测
npm run film:still -- --frame=3050        # 换时间轴后先看这一帧
npm run export:mp4 && ffprobe out/one-rule-infinite.mp4
```

浏览器里：把「每个节点的分支数」拉到 4，枝条数要真的涨上去；把枝条长度衰减调到 95%，
树要真的变成细长的一根；点开一个琥珀色环的节点，前置数量要真的不止一个；
点「换一片宇宙」，宇宙网要真的换一张；缩到 390px 宽，不允许出现横向滚动条。

## 遗留问题

- 手机竖屏下 16:9 的字幕偏小，页面已提示横屏或全屏；根治需要单独一版竖屏 Composition。
- 实验室的层数上限随分支数变化（`maxGenerationsFor`），是为了别让浏览器一次画上千根枝条。
- 叶片布局仍是「每根末梢枝条上放 3 片」，没有做叶序（phyllotaxis）级别的排布。
- 宇宙网是纯程序生成，没有接入真实的巡天数据（如 SDSS / 2MASS 的纤维图）。
