# 欧拉恒等式互动科普

一座可以亲手操作的数字展览馆：认识 e、认识 i、转一下单位圆、看 -1 与 +1 如何抵消，
最后自己回答三个小问题。全站八个场景由一条动画主线串起来，而不是八个互不相干的动画组件。

## 跑起来

```bash
npm install     # 已安装可跳过
npm run dev     # http://localhost:5173
npm test        # 数学计算的单测（vitest）
npm run build   # 类型检查 + 生产构建，产物在 dist/
npm run preview # 预览构建产物
```

## 做了什么

| 场景 | 内容 | 交互 / 控制 |
|---|---|---|
| 01 序章 | 光点进入 → 几何线条被「画」出 → e / i / π / 1 / 0 各自登场 → 组成公式 → 几何点亮后安静下来 | 跳过、重播 |
| 02 认识 e | 连续翻倍的种子 → 汇成一条上升曲线 → 光点沿曲线跑完 → 圆从终点展开 | 播放 / 暂停 / 重播 |
| 03 认识 i | 数轴 → 垂直轴长出（带 3D 展开）→ 复平面 → 乘以 i 两次：1 → i → -1 | 播放 / 暂停 / 重播 |
| 04 旋转实验室 | 单位圆实时拖动、角度滑块、自动旋转、五个特殊角度吸附、发光拖尾 | 拖动 / 滑块 / 播放 / 暂停 / 重置 / 特殊角度 / 轨迹开关 / 讲解重播 / 键盘方向键 |
| 05 走到 π | 0 → π/2 → π → 3π/2 → 回到 π，再一步步化简出 e^{iπ} = -1 | 播放 / 暂停 / 上一步 / 下一步 / 跳转某一步 |
| 06 为什么是 0 | -1 与 +1 长度相同方向相反，相向移动，在原点抵消 | 播放 / 暂停 / 重播 / 下一步 |
| 07 五个常数 | e / i / π / 1 / 0 依次点亮，点一下看它做过什么 | 点选、逐个点亮 |
| 08 你来试试 | 三道题，答错给提示可重试，答对播放对应的小动画 | 选择、重做 |

## 工程上的关键决定

- **角度只有一个来源。** `src/state/rotationStore.ts` 是唯一可信状态，
  用 `useSyncExternalStore` 订阅；同时导出一个 `MotionValue` 给 SVG 图形直接订阅，
  所以每帧只有几何在动，不会引发整棵组件树重渲染。拖动、滑块、自动旋转、
  特殊角度按钮全部写同一个 `rotationStore.setTheta`，因此点、向量、圆弧、投影、
  cos/sin 读数不可能不同步。
- **数学计算与渲染分离。** `src/lib/math.ts` 是纯函数（角度归一化、单位圆坐标、
  特殊角度判定、浮点清洗、SVG 圆弧路径），有单测；`src/lib/format.ts` 只管怎么把数字写成字符串。
- **时间轴复用。** `usePhaseTimeline`（rAF 驱动，阶段切换才触发 React 渲染）被
  场景 05 / 06 共用；`useSequence` 服务于更简单的分步叙事。
- **SVG 圆弧用虚线画。** 把 `pathLength` 归一化为 1，再用 `stroke-dasharray` 表示
  「画到路径的百分之几」，就不用自己算弧长（`src/components/DashPath.tsx`）。
- **降级。** 监听 `prefers-reduced-motion`：开启后所有场景直接停在关键结论上
  （点已经在 π、公式已经化简完、五个常数都在），信息量不减，只是不再播放。

## 数学上刻意保持的准确

- 欧拉公式 `e^{iθ} = cos θ + i sin θ` 与欧拉恒等式 `e^{iπ} + 1 = 0` 在页面上分开称呼。
- 特殊角度（0、π/2、π、3π/2、2π）优先显示精确值，不会出现 `-0.000`；
  普通角度实时更新到三位小数。
- 「乘以 i 就是转 90°」明确标注为直观模型，并说明一般情况下复数相乘还会改变长度。
- 场景 02 提前说明：增长讲大小、旋转讲方向，e^{iθ} 的模长恒为 1。
- SVG 的 y 轴向下，所有角度都经过 `toSvgPoint` 翻转，避免出现上下颠倒的投影。

## 怎么打倒它

- 打开旋转实验室，把点拖到 π 附近 —— 投影、cos/sin、坐标、公式代入必须同时变。
- 关掉动画（系统里开「减少动态效果」）后逐屏翻 —— 每一屏仍然要能读懂结论。
- 改 `SPECIAL_ANGLES` 或 `arcPath` 后跑 `npm test`，单测会盯着归一化与弧长。
- 缩到 360px 宽 —— 不允许出现横向滚动条，公式不能溢出。

## 遗留问题

- 首屏公式用 HTML 字形排版（为了逐个编排入场），和页面里 KaTeX 的公式是两套排版；
  间距是手调的，换字体时需要再看一眼。
- 场景 02 的翻倍示意最多画到 16 个点，再多就要换布局（例如改成分叉树）。
- 构建产物单包约 610 KB（gzip 约 190 KB），主要来自 motion 与 katex；
  如果要进一步优化，可以按路由做代码分割。
