# 重新审视：跑出来的、坏的、砍掉的

这条实验分三轮记：

1. **第一轮** —— 把它缩到只剩「能跑通、能被推翻」的部分，并定下砍掉哪些东西。
2. **第二轮**（第六节）—— 接通真实 API，顺带挖出两个从来没被触发过的 bug。
3. **第三轮**（第八节）—— 把「猜」换成「量」，做了 2×2 对照和概率探针。

**下面每一条都是跑出来的，不是读出来的。跑不出来的部分明确写着「没跑」。**

---

## 一、第一轮：砍了什么，为什么

这个项目从一个更大的前身版本里拆出来（那个仓库不公开，这里不引用它）。
拆的时候只问一件事：**留下的部分，跑得起来吗？能被推翻吗？**

### 1. 三个代码层面的问题

**(a) 「什么方向合法」有两份实现。**
引擎判定「这一步会不会撞死」有一份，给模型看的候选方向列表又有一份。
两处逻辑必须永远一致，否则就会出现「模型被要求选一个会自杀的方向」。
靠人肉维持这个不变量，是典型的铁墓。

**处理**：合并成 `SnakeGame::legal_directions()` 一份。发给模型的 choice、
模型返回的方向、引擎接受的，物理上不可能对不上。

**(b) 假 client 证明不了协议是对的。**
原来的 mock 只是按顺序吐出预设响应，**它不校验请求、不看 criteria、不看 state**。
所以所有基于它的测试证明的是「我 mock 的东西能被我自己的 parser 解析」，
而不是「真实 API 会返回这样的东西」。

**处理**：把 mock 从「客户端里的假数据」改成「真的本地 HTTP 服务」
（`src/mock.rs`）。服务端会读请求、会按你给的 criteria 回答案，
还会把收到的请求体存下来供断言。

**(c) 一个兼容层在误导下一个人。**
`complete()` 实现了 OpenAI 风格的签名（`Vec<ChatMessage>` → `ChatResponse`），
内部调的却是 `/v1/systemone`，再把结构化答案 pretty-print 成文本塞回去。
`/v1/systemone` 根本不吃 chat 消息，这层存在的唯一理由是历史包袱。

**处理**：删掉。`JevClient::decide()` 直接收发结构化类型。

### 2. 规模：实验是 15%，界面是 48%

前身版本里，`src/ui/` + `src/theme/` + 文案 + 配置加起来占 48% 的 Rust 代码，
而实验本体（引擎 + 协议 + 决策）只占 15%。最说明问题的一个数字：
单文件 925 行，只用来把星神 logo 画成终端像素图 —— 这条实验一个字都没提到它们。

### 3. 砍掉的，逐条记账

| 砍掉的 | 理由 |
|---|---|
| 全部主题 / 像素 logo / 中英双语 | 为了看；实验要的是量 |
| 子进程 bot 协议与沙箱 | 另一条实验；且它自己承认没有 OS 级网络隔离 |
| 持久化配置 | UI 的持久化 |
| 1.6 MB 的 logo PNG | 实验用不上 |
| 玩家手册 | 讲界面怎么用 |
| phantom 的两档人格 | 玩法，不是这个实验要回答的问题 |
| OpenAI 兼容层 | 见上文 (c) |
| `rand` 依赖 | 自己写 15 行确定性 PRNG，seed 契约可读可测 |
| UI 调速档位 | 对模型源不生效（见第六节） |

### 4. 后来加回来的：界面

**第一轮砍掉全部界面的理由有一半是错的。**
「实验要回答的是量，不是看」—— 这句话本身没错，错在把它当成了终局判断。

对的那一半：主题、像素 logo、双语、12 套调色板，和这条实验确实没关系。

错的那一半：**「看」不是「装饰」。** 一条关于 LLM 决策的实验，
最该被看见的恰恰是「模型每一步选了什么、有多确定、代价多少」——
概率分布用一条横条比一列 JSON 直观得多，延迟从 p50/p95 变成一行行滚动的流水。

所以加回来的不是原来的界面，是**围绕这条实验重画的一个**：只画决策信息。

> 经验：实验做到某个阶段，工具就该跟着阶段变 —— 加回来的时候记清楚为什么加，
> 比假装一开始就 planned 好。

### 5. 一个被推翻的技术决定

第一轮把「后台线程 + 状态机」一起砍了，理由是「测量台宁可阻塞，让延迟摊在墙钟上」。
这条理由本身没错，但有了界面之后它必须回来 —— 不是原样搬，而是以另一个理由：
**如果决策在主线程上阻塞，屏幕会在每次网络往返期间冻住。**
而「往返有多长」正是这条实验最该被看见的现象。

### 6. 第一轮结束时，没回答的问题

- **Jev 到底会不会玩贪吃蛇？** 不知道。连不上。（第二轮答了：会）
- **它比随机走强多少？** 不知道。需要真数据。
- **`probabilities` 有没有信息量？** 不知道。拿到的每一个数都是 mock 自己编的。
- **一次请求问 N 步行不行？** 没试。
- **「模型比随机走强」这条结论稳不稳？** 5 个 seed 证不了「稳」，
  只能证「不是偶然」。

## 六、第二轮（2026-10-17）：跑通了，顺带挖出两个被藏住的 bug

起因是一个很小的问题：「那条 451 是不是因为 Jev 的 API 改了？」
答案是**不是**，但查下去挖出来的东西比原来的问题重要。

### 1. 451 是地区拦截，和 API 改动无关

和当天的 `docs.typesafe.ai/api` 逐字段核对：端点、Bearer 认证、`model` 别名、
choice 的 `type`/`instructions`/`criteria`、响应的 `model`/`answers`/`usage` ——
**一个字段都没变**。

决定性的一组探测：451 是在**一层前置的地理网关**上返回的，连请求体都不校验 ——
非法 JSON 返 451（不是 400），不存在的路径返 451（不是 404），不带 key 返 451
（不是 401）。

推论值得单独写一句：**在这个网络环境下，任何 API 改动都不可能被观测到。**
「跑不起来」和「API 变了」这两个解释，从证据上无法区分 —— 直到找到代理。

### 2. `TcpStream` + `native-tls` 完全不认代理变量

这一条解释了为什么「换个环境跑」的建议从来没被试过：README 里写着
「换地区**或走本地代理**」，但「走本地代理」这半句**是假的**。

`src/jev.rs` 是手搓的裸 TCP + 手写 HTTP/1.1 报文，没有 reqwest / ureq / hyper，
所以没有任何一层会去查 `HTTPS_PROXY`。实测：把 `HTTPS_PROXY` 指向一个死端口，
`curl` 立刻连不上，而 jev-snake 照样拿到 451 —— 它根本没看那个变量。

加上代理支持（HTTP CONNECT + SOCKS5，`src/proxy.rs`）之后，同一个请求回 **200**。

### 3. `Transfer-Encoding: chunked` —— 一个从来没被触发过的 bug

代理打通之后，第一次真实调用报的是：

```
invalid response: 解析响应失败：expected value at line 1 column 1
```

原因：真实 API（Cloudflare 在后面）回的是 `Transfer-Encoding: chunked`，
而原来的 `split_status_and_body` 只是按第一个空行一刀切，
于是把 chunk 帧（长度行 + JSON + 结束块）当 JSON 喂给了 serde。

**这个 bug 之所以藏了这么久，是因为这个客户端从来没收到过真实 API 的成功响应。**
直连永远是 451；本地 mock 永远发 `Content-Length`，永远是良构的。

也就是说，第一轮那套「协议路径已验证（47 个测试全绿）」的结论，
验证的其实只是**我们自己和自己的 mock 之间的默契**。
这是这个项目最该记住的一条：

> **一个从没被真实数据碰过的路径，测试全绿不等于它是对的。**

修法是老老实实实现三种传输方式（chunked / Content-Length / 读到 EOF），
并用「每次只给 3 字节」的假 socket 测读边界落在 chunk 帧中间的情况。

### 4. 「蛇一直向右」是提示词的产物，不是模型不会玩

打通之后第一次真跑，12 步全选 `right`，得分 0 —— 和 `FINDINGS` 里记的那个
「snake just goes right forever」一模一样。当时的归因是引擎结构：
模型源只在决策到手的那一 tick 才 `game.tick()`。

**结构那部分归因没错，但它解释不了「为什么每次都选 right」。**
核对文档时顺手改了两处：

1. `instructions` / `criteria` 从中文改成英文 —— 文档明说 Jev 主语言是英语，
   CJK「accepted but currently have lower accuracy」。
2. `state` 从「JSON 塞进字符串」改成直接传 JSON 对象 —— 文档推荐
   "Use an object for most requests so each part of the state has a descriptive name"。

改完再跑，同一个模型、同一个 seed：

```
 2  0  ( 6, 4)  ( 3, 0)  up      0.46
 5  0  ( 6, 1)  ( 3, 0)  left     0.27
 8  0  ( 3, 1)  ( 3, 0)  up       0.58
 9  1  ( 3, 0)  (15, 7)  right    0.98   <- 吃到食物
21  1  (15, 0)  (15, 7)  down     0.34
```

**它会寻路、会吃到食物。** 之前那个「一直向右」，是我们自己的提示词造成的。

诚实的边界：这两处是**同时**改的，没有做 A/B。到底是语言、还是结构、
还是两者叠加，这条**没有回答**，别当成已回答。

### 5. 置信度和正确率脱节

实测里走向正确的一大批步，置信度只有 0.14~0.32；反而吃到食物那一步是 0.98。

这直接打掉了「低置信度时把控制权交回本地算法」那条设想 ——
那等于把走对的那批决策也一起交出去。样本还很小，但方向是明确的坏消息。

### 6. 代价没变，而且现在能量化了

839ms/步 ≈ **每秒 1.2 格**。同一台机器上 `greedy` 跑完一局 42ms。

所以这条实验现在能回答那个真正的问题了：

> **Jev 会玩贪吃蛇。** 但它比 `greedy` 慢四个数量级，而得分更低
> （24 步得 1 分 vs `greedy` 平均 15.8 分）。

「能不能选对方向」从来不是瓶颈，**每一步一次网络往返**才是。

## 八、第三轮（2026-10-17）：把「猜」换成「量」

第二轮留了三个问题，这一轮逐个去查。

### 1. 网络抖动伪装成了实验结论

跑对照实验时 `zh` 全是 0 分、`ticks=1`，看着像「中文提问有多差」。
真相是：

```
network: TLS 握手失败：the handshake process was interrupted
```

**20~37% 的请求在传输层就死了**，而默认行为是遇错停手，于是第一次抖动把整局掐断。

修法：只对**传输层**错误重试。`Http`（451/429/…）是服务端的回答，重试只是白烧
token；`Invalid` 是自己解析不出来，再来一次还是同样的坏数据。
**重试次数会被统计上报** —— 延迟统计因此含了重试，这是实测的诚实代价。

这一条值得单独记：**测量工具的故障模式，会伪装成被测对象的性质。**
如果当时没去核对「那 2 分 0 错误是怎么来的」，这个假象会直接写进结论。

### 2. 是语言，不是 state 编码

第二轮同时改了「提问改英文」和「state 传对象」，没做 A/B。
这次跑了 2×2：每格 5 个 seed、每局 30 步，共 20 局真实调用。

```
                      state=对象   state=字符串
   英文提问               2.20         1.80
   中文提问               0.20         0.60
   ----------------------------------------------
   编码边际               1.20         1.20

   语言边际：英文 2.00 vs 中文 0.40    差 +1.60
   编码边际：对象 1.20 vs 字符串 1.20  差 +0.00
```

**语言差 5 倍，编码一点用都没有。** 「state 双重编码」那个改动纯属误打误撞。

所以第二轮那条「改用英文提问 + state 传对象之后会寻路了」的因果是错的 ——
真正起作用的只有语言那一半。这和文档完全对得上：Jev 主语言是英语，
CJK「accepted but currently have lower accuracy」。

### 3. confidence 确实带信息 —— 但只关于「吃到东西」

加了 `--dump`，把每一步的 confidence、完整概率分布、是否吃食、是否致命都存下来。
120 步真实决策：

```
   confidence >= 0.5   73 步   吃到食物 9 步 (12.3%)
   confidence <  0.5   46 步   吃到食物 1 步 ( 2.2%)
```

**差 5.6 倍，方向是「高置信度对应吃到东西」。** 这推翻了第二轮那个
「置信度和正确率脱节」的印象 —— 那 24 步样本太小，不该下结论。

另外两条：

- **模型永远选概率最大的那个选项**（119/119）。所以 `probabilities` 不是独立
  的决策信号，是模型内部状态的**读数**。
- 模型比想象的确定：选中方向的中位概率 0.73，90 分位 1.00。

**没答上的**：那 120 步里一局都没死，所以「confidence 能不能预测撞死」
**根本没被测到**。要回答它得先跑几局会死的。

### 4. 一次问 N 步：省得下往返，省不下时间

`JEV_PLAN=3`：把问题换成「这 3 步按什么顺序走」，拿回路线后本地一步步验着走，
只有下一步在当前棋盘上不再合法时才重新问。

```
              网络往返   每往返换几格   重试   墙钟
   JEV_PLAN=1      20         1.00       0    26.9 s
   JEV_PLAN=3       7         2.86       5    24.6 s
```

**往返少了 65%，墙钟几乎没变** —— 因为这局撞上 5 次重试，而失败的握手要等
好几秒才报错。省下的往返被失败吃掉了。

但换一个**没碰上重试**的局，结论就反过来了（seed 42，12 步，0 重试）：

```
   JEV_PLAN=3    4 次往返   4.5 s   每秒 2.6 格
   JEV_PLAN=1   12 次往返  10.8 s   每秒 1.1 格
```

**网络干净的时候快 2.4 倍。** 所以不是「优化没用」，是**被噪声淹了**。

结论：**两个都要。** 规划有效，但先修网络，否则你根本测不出它有没有效 ——
这正好又是「测量工具的故障模式会伪装成被测对象的性质」那条。

### 一条记给下一个人看的

第二轮我记的是「测试全绿不等于路径对，因为没被真实数据碰过」。
这一轮补上后半句：

> **测量工具的故障模式，会伪装成被测对象的性质。**

第一轮那次「中文差」不是模型的性质，是网络的性质。
而把它当成模型的性质写进结论，只用了五分钟 —— 拆掉它用了一整轮实验。
